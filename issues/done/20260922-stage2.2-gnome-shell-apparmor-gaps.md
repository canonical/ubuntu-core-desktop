# gnome-shell confined per-app profile: remaining AppArmor gaps

Date: 2026-09-22

## Impact / Priority

gnome-shell was already running confined as its own app
(snap.ubuntu-desktop-session.gnome-shell, enforce), but three AppArmor
gaps remained, all denied at GUI-interaction moments a user actually
hits: the login1 `GetSessionByPID` lookup, the shell's own cgroup
`cpu.max` reads, and the (hardware-optional) fprint device probe.
Impact derived from the original note's symptoms.

Step 5 of `20260922-stage2.2-unblock-greeter-collision.md`.

## Context

gnome-shell now runs confined as its own app
(snap.ubuntu-desktop-session.gnome-shell, enforce) after the slot fix
(wayland/x11) and snap-run routing. A complain-mode / enforce-denial
pass over a live session found exactly THREE distinct gaps. All three
are simple rule additions to EXISTING interfaces — none need a new
interface or architectural work. This is the folded deliverable of
Step 5; the actual interface edits + rebuild are the follow-on.

Note on method: aa-complain is NOT available on the VM (only
apparmor_parser + aa-status). Use `apparmor_parser -r -C <profile>` to
switch a profile to complain and `apparmor_parser -r <profile>` to
revert. However, complain mode only logs when the operation is
*actually attempted* and the denied ops (fprint check, cgroup reads,
login1 calls) happen at GUI-interaction moments not reproducible over
SSH, so the enforce-mode DENIED lines below are the practical gap list.

## The three gaps (gnome-shell, enforce mode, deduplicated)

1. D-Bus member GetSessionByPID on org.freedesktop.login1.Manager

       denied: dbus_method_call bus=system path=/org/freedesktop/login1
               interface=org.freedesktop.login1.Manager member=GetSessionByPID
               label=snap.ubuntu-desktop-session.gnome-shell peer_label=unconfined

   CAUSE: interfaces/builtin/login_session_observe.go allows
   member=Get{Seat,Session,User} and List{Seats,Sessions,Users} but NOT
   GetSessionByPID. The plug IS connected (manual) and the profile has
   25 login1 rules, but 0 for GetSessionByPID.

   FIX: add `member=GetSessionByPID` to the login-session-observe
   connectedPlugAppArmor `dbus (send)` rule for login1.Manager.

2. D-Bus member GetDefaultDevice on net.reactivated.Fprint.Manager

       denied: dbus_method_call bus=system path=/net/reactivated/Fprint/Manager
               interface=net.reactivated.Fprint.Manager member=GetDefaultDevice
               label=snap.ubuntu-desktop-session.gnome-shell

   CAUSE: no fprint interface/rule exists at all.

   FIX (lower priority, arguably benign): either add a narrow fprint
   D-Bus rule, or document this as an accepted denial for systems
   without a fingerprint reader. Fprint is hardware-optional.

3. File read /sys/fs/cgroup/user.slice/user-1000.slice/user@1000.service/
   app.slice/cpu.max (and sibling cgroup v2 cpu files)

       denied: operation=open class=file requested_mask=r
               comm=blocking-*  (gnome-shell task scheduler threads)

   repeated frequently (every blocking operation).

   CAUSE: interfaces/builtin/system_observe.go grants
   /sys/fs/cgroup/system.slice/cpu.max r (and cgroup v1 cpu paths) but
   NOT the user.slice/user-* hierarchy. gnome-shell's scheduler reads
   its own cgroup's cpu.max under user.slice.

   FIX: add a cgroup v2 user-slice cpu rule to system-observe, e.g.
   /sys/fs/cgroup/user.slice/user-@{uid}.slice/**/cpu.max r, (or the
   snapd equivalent owning-path form). Confirm the exact uid templating
   syntax against how system-observe already grants
   /sys/fs/cgroup/system.slice/cpu.max.

## Mapping to interfaces (all three live in ubuntu-core-desktop-snapd)

- login_session_observe.go  -> gap 1 (GetSessionByPID)
- system_observe.go         -> gap 3 (user.slice cpu.max)
- (new or accept)           -> gap 2 (fprint GetDefaultDevice)

Note these same gaps will likely apply to the gsd-* per-app profiles
once they are re-confined after the full core-base-desktop rebuild;
re-run this pass then.

Result of the Step 5 complain-mode enumeration: COMPLETE. Findings
above.

## Follow-on fix status (final, verified on a clean boot 2026-09-22)

- Gap 1 (GetSessionByPID): FIXED in
  interfaces/builtin/login_session_observe.go.

  Important gotcha + the fix path:

  - First attempt put GetSessionByPID inside the existing
    Get{Seat,Session,User} alternation, which expands to
    GetGetSessionByPID (the member already has its own Get prefix), so
    it never matched and the denial persisted.
  - Correct fix: GetSessionByPID is its OWN dbus (send) rule so the
    member name is emitted verbatim. (commit 13a2864559)

  Verified: 0 GetSessionByPID denials on clean boot.
- Gap 3 (user.slice app.slice cpu.max): FIXED in
  interfaces/builtin/systemd_user_control.go (added the
  .../user@[0-9]*.service/app.slice/cpu.max rule). Verified: 0 cpu.max
  denials.
- NEW (surfaced after fixing gap 1): CanRebootToBootLoaderMenu on
  login1.Manager — gnome-shell probes logind for the bootloader-menu
  capability at login. Same category as GetSessionByPID, its own
  dbus (send) rule. (commit 7e1160f609) Verified: 0 denials.
- Gap 2 (fprint GetDefaultDevice): DEFERRED / ACCEPTED AS BENIGN.
  fprintd is hardware-optional; the probe is denied and gnome-shell
  falls back to no-fingerprint. A proper fprint interface needs
  upstream design review. Do NOT add a one-off rule here.

## Remaining (pre-existing, not part of this fold-in)

- bwrap userns_create denied (`20260918-bwrap-userns-create-denied.md`)
- org.freedesktop.DBus Properties GetAll denied (from a bwrap-launched
  child process; same bwrap issue family)

Final verified state (clean boot): gnome-shell confined as
snap.ubuntu-desktop-session.gnome-shell (enforce); 0 denials for
GetSessionByPID / cpu.max / CanRebootToBootLoaderMenu; only the
known-benign fprint + pre-existing bwrap denials remain.

## Resolution (2026-09-28)

The three gaps in this note were fixed and clean-boot verified:
`GetSessionByPID`, the user-slice `cpu.max` read, and
`CanRebootToBootLoaderMenu`. The optional fprint probe remains an
accepted denial. The related snapd commit references recorded above are
13a2864559 and 7e1160f609.

This closes only this gnome-shell gap list. The parent
`20260922-split-core26-desktop-base-snap.md` still tracks other
D-Bus-activated services that have not been routed and verified under
their per-app snap profiles.
